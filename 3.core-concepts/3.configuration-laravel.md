# Configuration (Laravel)

In Laravel, Apie is configured via the `laravel-apie` package. After installing the package, you can publish the configuration file using:

```bash
php artisan vendor:publish --provider="Apie\LaravelApie\ApieServiceProvider"
```

This will create a `config/apie.php` file.

## Basic Configuration

The configuration file allows you to define your bounded contexts and enable/disable specific Apie features. In version 1.0.0, the configuration is wrapped in `ValidateAndSanitizeConfig::process()` to ensure all settings are correctly validated.

```php
use Apie\LaravelApie\Config\ValidateAndSanitizeConfig;

return ValidateAndSanitizeConfig::process([
    'bounded_contexts' => [
        'default' => [
            'entities_folder' => app_path('Apie/Entities'),
            'entities_namespace' => 'App\\Apie\\Entities\\',
            'actions_folder' => app_path('Apie/Actions'),
            'actions_namespace' => 'App\\Apie\\Actions\\',
        ]
    ],
    'rest_api' => [
        'base_url' => '/api',
    ],
    'cms' => [
        'base_url' => '/cms',
    ],
    // ...
]);
```

## Configuration Options

- `bounded_contexts`: Define the location and namespace of your domain objects and actions.
- `rest_api.base_url`: The prefix for your REST API routes.
- `cms.base_url`: The prefix for your CMS (admin panel) routes.
- `datalayers`: Configure how Apie should store and retrieve your objects. By default, it uses an in-memory data layer for development.

## Automatic Feature Detection

Apie automatically detects which packages are installed and enables the corresponding features (like REST API, CMS, Faker, etc.) if they are present in your `composer.json`.
