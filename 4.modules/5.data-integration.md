# Data Integration Module

Apie provides several ways to persist and retrieve your domain objects, allowing you to choose the best storage engine for your needs.

## Data Layers

Data layers are the bridge between your domain objects and the physical storage. Apie supports multiple data layers:

- **In-Memory**: Used by default for rapid development and testing. Data is lost when the process terminates.
- **Doctrine ORM**: The `apie/doctrine-entity-datalayer` package provides integration with Doctrine, allowing you to use SQL databases.
- **File System**: The `apie-file-system` package allows storing objects as files (e.g., JSON or YAML).

## Key Features

- **Object-Relational Mapping (ORM)**: Automatically maps your domain objects to database tables (using Doctrine).
- **No Mapping Required**: Apie can often infer the database schema directly from your domain objects.
- **Repository Pattern**: Apie provides a consistent interface for querying objects across different data layers.

## Usage (Doctrine)

1. Install the package:
   ```bash
   composer require apie/doctrine-entity-datalayer
   ```
2. Configure your database connection in your framework.
3. Apie will handle the mapping and persistence of your `EntityInterface` objects.
